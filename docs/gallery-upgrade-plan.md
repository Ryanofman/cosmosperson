# cosmosperson.com — gallery upgrade: research and plan

Written 30 October 2026. For Ryan, and for any session picking up the gallery work.
Sources: a live audit of cosmosperson.com, a survey of 19 astrophotography sites and 10
fine-art photography portfolios, a review of gallery libraries and static-hosting options,
and a format test on three of the site's own images. Everything was checked on the day;
where something could not be verified it says so.

---

## 1. The verdict in ten lines

1. The site's bones are right: a static site, one JSON file as the source of truth, an
   admin that publishes through GitHub. Keep all of that.
2. The gallery itself is a hover-grid plus a lightbox. World-class astro galleries are
   built around the **image page**: a permalink, a technical card, deep zoom, provenance.
3. The single biggest gap is data. Every `capture` block in `gallery.json` is empty, so the
   site cannot show integration, filters, gear, nights or location for any photo.
4. The grid is CSS-column masonry, so the order you set in the admin is not the order the
   eye reads, and wide mosaics shrink to a third of the width.
5. The viewer goes black for two to three seconds, shows tall images at only ~1400 px, and
   collapses the image to a thumbnail when the details drawer opens.
6. Nothing exists for deep zoom, plate-solved annotations, palette variants (SHO / HOO /
   starless), download sizes, prev/next by collection, or share previews per photo.
7. On phones the grid has no captions at all and the viewer leaves half the screen empty.
8. The image pipeline is JPEG-only. AVIF at the same fidelity is about 40% smaller on your
   images (measured below), and deep-zoom tiles can be generated by the same build.
9. The Explore page is a single point of failure: it loads Aladin Lite from Strasbourg, and
   that server was unreachable from here today, leaving the page blank.
10. Recommendation: rebuild the gallery around a richer `gallery.json` (schema v3), a build
    step that runs in GitHub Actions, pre-rendered photo pages, a justified-row index, and
    an admin that edits everything, including layout and site settings. Phases in section 6.

## 2. Where the gallery stands today (audit, 30 Oct 2026)

The live site is the same code as this folder; it was last deployed on 26 July 2026
(repository `Ryanofman/cosmosperson`, public, 300 MB, GitHub Pages).

**Index**
- `column-count: 3` masonry. Items flow down each column, so the curated order is not what a
  visitor reads left to right. Six portrait crops at roughly 1:2 dominate the page; the four
  wide mosaics (California, Thor's Helmet, Soul, Eastern Veil) get a third of the width.
- Captions appear on hover only, so touch devices see anonymous images. No search, no sort,
  no constellation, season, year, palette or telescope facets. Four category tabs.
- The scroll-reveal animation left the grid blank when the page was scrolled quickly.

**Viewer**
- The 2600 px derivative paints two to three seconds after opening, with no placeholder.
- `srcset` uses width descriptors, so a 3916 × 7216 image's largest file is 1411 px wide.
- The details drawer pushes the image up until it is a thumbnail.
- Zoom is a CSS 1:1 pan of the 2600 px derivative, not the full image. "Full Resolution"
  opens the raw 10 to 22 MB original.
- No capture data, annotations, palette variants, download ladder, related images, prints or
  share control. Deep links (`#photo=id`) and history work well.
- Mobile: a wide image is letterboxed with most of the screen empty; actions wrap to three
  lines.

**Data and pipeline**
- `gallery.json` v2 is the single source of truth. It has no fields for versions or palettes,
  per-filter acquisition, nights, collections, featured or layout hints, tags, alt text,
  tiles, annotations, licence or story.
- Derivatives: JPEG q82 at 800 / 1600 / 2600 long edge. No AVIF or WebP, nothing above
  2600 px, no tiles.
- Originals are 2× and 3× upsampled JPEGs of 0.2 to 22 MB. Several are stored twice
  (`gallery/` and `images/`). Two originals are not in the manifest: the Eagle (SHO) and the
  Lagoon (SHO).
- The admin generates derivatives on a browser canvas, which drops the ICC profile and
  encodes at 0.85. It can reorder, hide, edit text, set the hero and upload. It cannot manage
  collections, per-filter rows, versions, layout options, site settings or tiles.
- `explore.html` depends on jQuery and Aladin Lite from CDNs. The Aladin host timed out from
  this machine (browser and direct request), so the page rendered "Charting the sky" forever.

## 3. What the best galleries do

Nineteen astrophotography sites were examined, each at the index and at one image page,
with the page source inspected for libraries and image attributes. Ten general photography
portfolios were examined the same way. The full per-site records are in the research notes;
this is the synthesis.

**The pattern that separates the top tier**
- The image page is the product. AstroBin, Nebula Photos (Nico Carver), Telescope Live and
  ESA/Hubble all lead with a permalink page that carries a structured technical card: a
  per-filter table (filter, sub length × count, total, dates, moon), totals, nights, location
  and Bortle, optics, camera, mount, filters, software, RA/Dec centre, field of view, pixel
  scale and orientation. Nebula Photos lists all 71 nights and 9 sites of a 213-hour mosaic.
- Deep zoom exists only where the site is serious: ESA/ESO (OpenSeadragon on DZI tiles) and
  Nebula Photos (Zoomify). ESO shows a 6000 px panorama as a 700 px thumbnail and sends you to
  the zoomable view. Nobody else offers it, which makes it a differentiator.
- Plate-solving is exposed, not hidden. AstroBin draws catalogue labels and an RA/Dec grid as
  an SVG overlay on hover, with "view sky map", Moon scale and measure tools. ESA/Hubble puts
  an Aladin Lite panel with a crossfade slider between the image and DSS2 on every page.
- A download ladder with honest labels: ESA lists "Fullsize TIFF 385 MB / Large JPEG 42 MB /
  Publication JPEG 2 MB / Screensize 213 KB"; Dylan O'Donnell writes "Download Full Resolution
  (757x491) 187KB". A licence line sits next to it.
- Palette variants on one page. Martin Pugh shows the SHO and the HaLRGB of M16 together with
  dated revisions; Nicolas Outters files SHO, SHO-RGB and HaOIII-RGB as a taxonomy; AstroBin
  keeps a revisions strip. No site offers a per-channel (Ha / OIII / SII / starless) toggle.
  That is an open opportunity for a narrowband imager.
- The story. Ivan Eder gives every image a title and an explanatory subtitle, sky-condition
  scores (transparency, seeing) and four recommended photos. Royal Museums Greenwich structures
  the winners' pages as "how it was made". Robert Gendler wrote 140 object essays.
- Chronology and navigation. Adam Block chains releases ("Previous Release", release date);
  Ciel Austral groups the index by season and captions each tile with date and telescope;
  AstroBin computes "images in the same area" from coordinates.
- Credibility signals: APOD badges linking to the APOD page (Ciel Austral, Pugh), AstroBin
  links, a copyright or licence line.

**Index layouts that work for astro**
- Justified rows (Adam Block, 309 px rows; Sara Wager, 174 px rows) and masonry (Nebula
  Photos, AstroBin) preserve native aspect ratios. Uniform squares (deography, Ciel Austral,
  Pugh) crop mosaics and lose the subject. Fine-art sites (Meyerowitz, Nick Brandt) skip the
  grid and show one image at a time with a thumbnail strip; that suits twenty images, not a
  growing collection.
- Captions are sparse everywhere: title, catalogue, and at most a date or telescope. Nobody
  shows integration hours on the card. Cheap to add, and visitors who image will read it.
- Facets seen: object type, catalogue family (Messier / NGC-IC / Sharpless / LBN-LDN),
  palette, constellation, season or year, telescope, sort by date or ranking, text search
  (Telescope Live's chips are the best model).

**Technical hygiene: almost nobody has it**
- The famous imagers' own sites (Nebula Photos, Adam Block, Gendler, Ciel Austral, Wager,
  Deep Sky Colors) ship zero `srcset`, zero lazy loading and zero WebP or AVIF. Only platform
  sites (Wix, Shopify, Squarespace, Kadence WordPress, Drupal) do, and those bury the images
  in 28 scripts, ads or SPAs that crawlers cannot read. A static site with a build step beats
  nearly all of them, and the current site already beats most on this.
- Dark is the genre norm: Deep Sky Colors and Wager are black, Telescope Live and astrofalls
  near-black, Nebula Photos and AstroBin mid-grey. Tan (Block), light grey (deography) and
  maroon (Pugh) visibly fight the images. Seven of nine general portfolios are light; the two
  dark ones are the moody documentary sites. Keep the near-black brand.

**Libraries worth using (licence and maintenance checked)**
- Lightbox: **PhotoSwipe 5** (MIT, 17 KB gzip, no dependencies; best pinch, drag-to-close and
  zoom engine; `srcset` aware). It dropped captions and hash links in v5, both easy to add.
  Fancybox is paid-only, lightGallery is GPL or paid, Spotlight is stale. GLightbox is a
  simpler MIT fallback. The current hand-written viewer could also be kept and improved; the
  gesture engine is where PhotoSwipe earns its place.
- Deep zoom: **OpenSeadragon 6.1** (BSD, 87 KB gzip) on DZI tiles, which is what ESA/ESO use.
- Sky: **Aladin Lite 3** (already on the site) for the footprint / crossfade panel;
  **nova.astrometry.net** API (free key) for plate solving, annotations and objects-in-field.
- Layout: a ~60-line justified-row algorithm (Flickr's `justified-layout`, ISC) rendered to
  the DOM, with a CSS-only flex fallback. Avoid Isotope and Flexbin (GPL or paid).
- Placeholders: **ThumbHash** (MIT, ~25 bytes per image, encodes aspect ratio and colour).

## 4. Format test on your own images

Three originals resized to 1600 px long edge, encoded with Pillow 12.3 (AVIF via libavif),
fidelity measured as PSNR against the resized source. Higher dB is closer to the source.

| Image | JPEG q82 4:2:0 (today) | JPEG q82 4:4:4 | WebP q90 | AVIF q65 4:4:4 | AVIF q75 4:4:4 |
|---|---|---|---|---|---|
| California (wide Hα, smooth gradients) | 153 KB · 34.2 dB | 222 KB · 35.1 dB | 213 KB · 36.0 dB | 132 KB · 35.6 dB | 190 KB · 36.6 dB |
| Whirlpool (galaxy, stars) | 104 KB · 40.2 dB | 162 KB · 41.6 dB | 97 KB · 40.8 dB | 62 KB · 40.2 dB | 94 KB · 40.8 dB |
| Eastern Veil (filaments, dense stars) | 155 KB · 36.1 dB | 225 KB · 37.6 dB | 180 KB · 38.2 dB | 131 KB · 37.9 dB | 202 KB · 39.2 dB |

Readings:
- Today's JPEGs use 4:2:0 chroma subsampling, which halves colour resolution. Star colour and
  Hα/OIII edges are sub-pixel chroma detail; 4:4:4 should be the floor for the JPEG fallback.
- AVIF q65 to q75 matches or beats JPEG q82 4:4:4 fidelity at roughly 40% smaller files.
- PSNR cannot see AVIF's known habit of smoothing fine texture, which on a star field means
  faint stars. Before locking the encoder, the build should write one AVIF and one JPEG of a
  dense field at the chosen quality for a side-by-side check at 1:1. Keep AVIF quality at
  70 or above and 4:4:4; never let the encoder subsample chroma.
- Encode times (1 to 3 s per 1600 px AVIF on this desktop) are fine for a build step and
  unsuitable for the browser-side admin. The pipeline belongs in a script or in CI.

## 5. The recommended design

### 5.1 Data: `gallery.json` schema v3

Still one file, still the single source of truth, still editable by hand or by the admin.
New per-photo fields (all optional, so existing entries keep working):

- `subtitle`, `story` (markdown), `alt`, `tags[]`, `collections[]`, `featured` (bool),
  `layout: { span: 1|2, focal: [x, y] }`, `licence`, `badges[]` (APOD, awards, with URLs).
- `object: { names[], type, constellation, distance, ra, dec }` replacing the flat fields,
  with the catalogue lookup still filling RA/Dec when the solve is missing.
- `acquisition`: `{ optics, camera, mount, filters[], guiding, software[], location,
  bortle, nights: [{ date, moon, notes }], subs: [{ filter, count, seconds }], total_seconds,
  conditions: { seeing, transparency } }`. Integration totals are computed, never typed.
- `solve: { ra, dec, pixscale, orientation, radius, fov: [w, h], objects[] }` from
  astrometry.net, plus `annotations` (label + pixel coordinates) for the overlay.
- `versions: [{ id, label: "SHO" | "HOO" | "Starless" | "Hα", original, derivatives… }]`.
  The first version is the default; the page shows a segmented toggle when there are two or
  more, and a crossfade slider for any pair.
- `mosaic: { panels, panel_map: [[x, y, w, h]…] }` for the panel overlay.
- `downloads: [{ label, url, width, height, bytes }]` written by the build, including the
  full-resolution link wherever originals end up living (decision 3).
- `tiles: { dzi, width, height, tile_size }` written by the build when tiles exist.
- `thumbhash` replaces the 1 KB base64 placeholder.

New `settings` block (what makes the site customizable without code):

- `hero: { id, version, focal }`.
- `grid: { style: "justified" | "masonry" | "uniform", row_height, gutter, captions:
  "always" | "hover" | "none", caption_fields[] }`.
- `index: { default_sort, facets[], show_counts, featured_first }`.
- `viewer: { open_as: "page" | "overlay", show_card_by_default }`.
- `theme: { accent, surface }`, `site: { title, tagline, statement, links[] }`.

### 5.2 Index page

- Justified rows computed from aspect ratios (row height from settings, 240 to 320 px on
  desktop), featured photos spanning a full row, mosaics never cropped. Masonry and uniform
  remain as settings for comparison. Manifest order is reading order.
- Captions under or over each tile from `caption_fields`: title, catalogue, integration,
  palette, year. On touch devices captions are always visible.
- Facets as chips with the state in the URL (`?type=nebulae&palette=SHO&sort=date`):
  object type, palette, constellation, year or season, catalogue family, collection; sort by
  curated order, date, integration; a text search over names and catalogue IDs.
- Loading: ThumbHash placeholder, `<picture>` with AVIF then JPEG, `srcset` by width with a
  correct `sizes`, lazy below the fold, `fetchpriority="high"` on the hero and first row.
- The scroll-reveal animation goes, or becomes a short fade that never hides content.

### 5.3 Photo page and viewer

- Every photo gets a real page at `/photo/<slug>/`, pre-rendered by the build from
  `gallery.json`: title, subtitle, the image, the technical card, the story, downloads,
  prev/next within the current collection, related photos (same constellation or within a
  few degrees by coordinates), OpenGraph and Twitter cards with a 1200 px preview, canonical
  URL, JSON-LD `ImageObject`. This is what makes a photo shareable and findable.
- The gallery keeps an overlay viewer for browsing fast; opening a photo updates the URL to
  its page, and a direct visit to the page renders the same layout without the grid.
- The viewer: PhotoSwipe 5 (or the existing viewer upgraded) with pinch, wheel zoom,
  drag-to-close, keyboard; a side rail for the technical card on wide screens and a bottom
  sheet on phones, so the image never shrinks to a thumbnail; placeholder shown instantly.
- Deep zoom: a "Zoom" control that swaps in OpenSeadragon on the DZI tiles for that photo
  (all photos, mandatory for mosaics), with the viewport in the URL hash so a crop can be
  linked. Fullscreen and keyboard supported.
- Annotations: a toggle that draws the plate-solved labels and an RA/Dec grid over the image
  (SVG, scaled with the viewer), a field-of-view badge, and a "Sky" panel that opens Aladin
  Lite centred on the solve with the image footprint drawn. "View on Sky Map" stays.
- Versions: segmented toggle (SHO / HOO / Starless / Hα) and a crossfade slider.
- Download ladder with pixel dimensions and file size in each label, plus the licence line.
- Mobile: image first at full width, then a compact card; swipe for prev/next.

### 5.4 Build pipeline

One Python script, `tools/build.py`, that runs the same way on your machine and in GitHub
Actions (Pillow 11.3+ encodes AVIF; `pyvips` optional for speed):

1. For each original and version: sRGB with the profile embedded, derivatives at 640 / 1024 /
   1600 / 2400 / 3200 long edge as AVIF (q70, 4:4:4) and JPEG (q85, 4:4:4, progressive),
   ThumbHash, dominant colour, EXIF stripped (no camera serial number ever ships).
2. DZI tiles (256 px, 1 px overlap, JPEG q80 or WebP) for every photo, into
   `tiles/<slug>/<version>/`.
3. Optional plate solve: submit the 1600 px derivative to nova.astrometry.net, store the
   calibration, objects-in-field and annotations in the JSON. Runs only for photos without a
   solve, so it costs nothing on later builds.
4. Pre-render `/photo/<slug>/index.html` pages and a sitemap from a template.
5. Write `gallery.json` back, preserving everything typed by hand.

The GitHub Action triggers on push when an original or the manifest changes, commits the
results with `[skip ci]`, and Pages deploys. The repository is public, so Actions minutes are
free. Ryan's workflow becomes: upload the original and fill the card in the admin, publish,
wait two minutes. Running `python tools/build.py` locally stays available for previews.

### 5.5 Admin v2

Keep the existing admin's model (fine-grained PAT, one commit through the Git Data API,
nothing live until Publish) and grow it:

- Photo editor with every v3 field: subtitle, story, tags, collections, featured, focal
  point picker, licence, badges; the acquisition card with per-filter rows and nights; a
  versions list with upload per version; a mosaic panel count.
- A Site tab for `settings`: hero and focal point, grid style and density, caption mode and
  fields, facets and default sort, theme accent, statement text, links. A live preview pane
  of the grid.
- Collections tab: create, name, describe, order, pick a cover.
- Upload: originals only; derivatives are left to the build (no more canvas encoding).
- Import: paste an AstroBin image URL to pre-fill the acquisition card from its public data
  (only if AstroBin's public API cooperates; to be confirmed when built).

Sveltia CMS was evaluated as the alternative: it signs in with a PAT, reorders lists by drag
and resizes uploads, with no server. It would replace the custom admin with a generic one
and lose the single-commit publish, the sky-aware fields and the live preview. The custom
admin is the better fit; Sveltia stays a fallback if the custom one becomes a burden.

### 5.6 Explore page and the rest

- Self-host Aladin Lite's JavaScript and CSS (LGPL, allowed) and drop jQuery, with a clear
  message and a link to the gallery when the sky survey tiles cannot load. Today's outage
  shows the page cannot depend on a single university server.
- Keep the brand: near-black surfaces, Cormorant Garamond and Inter, the teal accent, the cat.
- About page with the rig, the sites, the processing approach and a contact line, and the
  planned Rani page (its content and limits are already agreed separately).

### 5.7 Where the big files live

The repository is 300 MB now and GitHub recommends staying under 1 GB; single files are
blocked above 100 MB; Git LFS is not served by Pages. Tiles for the current collection
should add roughly 100 to 200 MB and every new 20 MB original stays in history forever.

| Option | Cost | Fit |
|---|---|---|
| Keep everything in the repo | Free | Fine for a year or two at the current pace; the 1 GB line arrives eventually |
| GitHub Releases for originals and tile archives | Free, no bandwidth cap, 2 GiB per file | Good for full-resolution downloads; awkward for tiles (an archive, not a folder) |
| Cloudflare R2 for originals and tiles | Free to 10 GB, free egress, then $0.015/GB-month | Best long-term home for tiles and originals; needs a Cloudflare account and a token in the Action |

Recommendation: start in the repo (fastest), with the build writing URLs through one base
path so moving tiles and originals to R2 later is a one-line change.

## 6. Phases

**Phase 1 — the new gallery (the biggest visible change)**
Schema v3 and migration of the 15 entries; `tools/build.py` with AVIF/JPEG/ThumbHash and
pre-rendered photo pages; the GitHub Action; the justified index with captions, facets, sort
and search; the new viewer with a side-rail card; mobile layout; Aladin self-hosted with a
fallback; the two missing SHO originals added. Acquisition data entered for every photo
(decision 6 is the gate for this).

**Phase 2 — the astro layer**
DZI tiles and OpenSeadragon; plate solving, annotations overlay, field-of-view badge, Sky
panel with footprint and crossfade; versions toggle and slider; download ladder; related
photos by coordinates; mosaic panel map.

**Phase 3 — admin v2**
Full v3 editor, Site and Collections tabs, live preview, originals-only upload, optional
AstroBin import. Until this lands, v3 fields can be edited in the JSON directly or through a
simplified form.

**Phase 4 — reach**
R2 (if chosen), About and Rani pages, JSON feed of new releases, JSON-LD, performance pass,
accessibility pass (captions in the DOM, alt text, focus order, reduced motion).

## 7. Decisions for Ryan

1. **Photo pages.** Pre-render a real page per photo at `/photo/<slug>/` (recommended), or
   keep everything inside the single-page gallery with hash links only?
2. **Build in GitHub Actions.** Agree to a workflow in the public repo that runs the Python
   build on push and commits derivatives, tiles and pages back? The alternative is running
   the script locally before every publish.
3. **Big-file hosting.** Repo for now with a base-path switch (recommended), GitHub Releases,
   or Cloudflare R2 from the start?
4. **Admin.** Extend the existing custom admin (recommended) or switch to Sveltia CMS?
5. **Plate solving.** Create a free nova.astrometry.net account and give the build an API
   key? It unlocks annotations, the Sky panel, field-of-view badges and related photos.
6. **Acquisition data.** How will the cards get filled: typed into the admin, a spreadsheet
   to import (one row per photo and filter), or AstroBin links to pull from? The gallery
   photos were clearly shot with more than one rig, so nothing will be assumed about optics
   or cameras.
7. **Scope.** Prints or sales in this upgrade (no is recommended; it changes the site into a
   shop), and should the Rani page be built in phase 4 or kept separate?
8. **Index default.** Justified rows is the recommendation; say so if you want masonry or a
   one-image-at-a-time presentation instead. All three remain available as a setting.

Not decisions, just notes: the Eagle and Lagoon SHO originals will be added unless told
otherwise; EXIF, including camera serial numbers, is stripped by the build; the current look stays.
